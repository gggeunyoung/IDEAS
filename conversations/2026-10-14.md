# 2026-10-14 — 토론에서 실제 목표 실행으로

## 사용자 의도와 발언

- 노젓기 게임의 입력 방식은 폰 IMU로 확정하지 않고 카메라 동작 인식과 비교하도록 요청했다.
- 회의실에서 Claude가 파일·셸 제한 때문에 구현하지 못했다는 답변을 받아, 밤새 실제 결과를 만드는 동작을 기대했다고 설명했다.
- 무한 실행은 원하지 않지만 구독 한도 안에서 목표 달성에 최선을 다하고, 불가능하면 이유를 남기거나 현장 검증 대기로 마무리하기를 원했다.
- 실행 규칙과 예산 조정을 해결하고 해당 회의실에서 다시 대화를 시작해, 자고 일어난 뒤 작은 결과라도 있기를 요청했다.

## 에이전트 제안과 실행

- 기존 토론은 독립 제안→검토 뒤 종료하며, CLI 셸·파일 도구와 목표 반복이 차단돼 있음을 실제 코드로 확인했다. 추가 계정 로그인 부족으로 안내하지 않았다.
- 첫 목표 실행 모드를 웹 시제품과 Node 내장 테스트 범위로 구현했다. AI의 구조화된 파일 제출→실제 저장→격리 검사→다른 AI 검토→수정 반복이다.
- 기본 예산은 60분·12회 호출이며, UI에서 시간과 호출 상한을 따로 선택한다. 실제 구독의 남은 토큰과 모델 사용량 보고를 혼동하지 않는다.
- 운영 규칙과 이번 목표는 docs/goal-execution-policy.md에 저장한다.

## 확정된 요구와 아직 제안인 설정

- 실제 실행 가능한 결과 우선, 가능한 작업부터 진행, 구현과 현장 실험 구분, 예산 안에서 반복은 사용자 요구다.
- 60분·12회 기본값과 첫 구현 범위는 이번 구현 선택이며 최적값이라고 확정하지 않는다.
- 원본을 직접 편집하거나 임의 명령·패키지를 실행하는 범용 개발 에이전트는 이번 모드와 별개로 남는다.

## 실제 파일·브라우저 검사와 보완

- 두 번째 실행은 실제 GPT 작성 3회, Claude 검토 2회와 시작 후 중단된 검토 1회를 시도했다. 첫 결과의 JS 문법 3개·실제 로직 테스트 10개가 통과했고, 브라우저 버튼에서 동기 좌우1회/6m, 엇박자4m, 손흔들기0회를 확인했다.

- 회의실 검토자가 선택적 개선과 범위 밖 후속 기능을 미완료 구현 목록에 함께 넣어 불필요하게 반복하는 문제도 발견했다. 필수 미완료와 suggestions를 분리하고 권장/후속 항목 때문에 최소 목표가 반복되지 않도록 수정했다. 이 재현을 포함한 전체 테스트는 47개 통과했다.
