## 확인된 원인
- GPT는 맥 ChatGPT/Codex 번들 CLI, Claude는 .local-tools의 Claude Code CLI를 사용한다. 구독으로 로그인한 별도 CLI 세션이며 앱 프로젝트 대화/설정/MCP를 통째로 상속하는 것이 아니다.
- 서버가 선택 자료를 snapshotFiles로 읽지만 runMeeting의 team 분기에서 context를 버렸다. 작업 트리에 없는 미커밋 자료는 파일 경로만 전달돼 내용이 빠질 수 있었다. 재현 검사로 확인했다.
- 모델과 사고 수준은 기본값에 맡겨 비교 조건이 불명확했다. 과거 Claude Opus5.5 보고는 있지만 과거 모든 GPT 호출의 모델/사고 수준을 확인한 것은 아니다.
- 리서치 역할에도 코딩/검사 중심의 상위 지시가 남았고 일반 대화 CLI는1500자 답변 지시가 있었다. 앱과 도구·기억·자료가 같다고 설명하지 않는다.

## 결정과 구현
- 선택된 원본의 안전한 현재 사본을 팀 모드 모든 차례에 전달한다. 미커밋 자료도 포함하고 작업 트리 파일과 구분한다.
- 구독 기본 요청 모델을 GPT gpt-6.1-sol, Claude claude-opus-5-5로 명시하고 사고 수준 high를 전달한다. .env의 LOCAL_*_MODEL/LOCAL_*_REASONING_EFFORT로 변경할 수 있다. API키를 사용하거나 임의의 저가모델로 대체하지 않는다. 높은 사고 수준은 구독 사용량과 지연을 늘릴 수 있다.
- 새 GPT 세션의 실행 기록에서 모델/사고 수준 메타데이터만 읽고 Claude의 실제 보고 모델을 읽는다. 모델 보고가 없으면 미보고, 명시된 모델과 다르면 오류로 처리한다. 다른 채팅이나 인증정보는 읽지 않는다.
- 리서치 역할을 조사/사용자 문제/아이디어 발전 중심으로 바꾸고 일반 대화의 기본 답변 허용 길이를6000자로 늘렸다. UI에 요청 모델·사고 수준과 답변의 CLI 보고 모델을 표시한다.

- 전체112개 중111개 통과/플랫폼 전용1개 제외. 미커밋 자료가 두 팀원에게 도달하고, 요청 모델/사고 인자가 전달되며, 다른 모델 보고는 거절하고, 정확한 세션의 모델 메타데이터만 읽는 검사를 포함한다. 정적 빌드/구문/공백 검사 통과.
