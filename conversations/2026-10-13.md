# 2026-10-13 — Vercel과 맥 에이전트 실제 연결

## 사용자 의도와 발언

- 원하는 것은 어느 기기에서든 https://ideas-nine-opal.vercel.app/ 에서 회의하면 현재 맥의 에이전트가 작업하는 경험이다.
- 로컬 회의실을 여는 방식은 이 컴퓨터에서만 사용할 수 있으므로 요구를 만족하지 않는다고 명확히 설명했다.
- Vercel 연동을 연결하겠다고 응답한 뒤 연결을 요청했다.

## 에이전트 제안과 실행

- 기존 로컬 기능 완료를 원격 사용 완료로 안내한 범위를 정정하고, 인증된 Vercel 중계와 맥 작업 실행을 구현했다.
- Vercel 연동으로 기존 ideas 프로젝트 접근과 production 환경 설정을 확인했다. 다른 프로젝트나 유료 플랜을 만들지 않았다.
- 웹 비밀번호 로그인, HttpOnly·Secure·SameSite=Strict 세션, 중계 인증키, 로그인 시도 제한, 허용된 API 경로와 중계 주소 검사를 추가했다.
- Vercel 함수는 맥 작업 ID를 제출/조회한다. GPT·Claude 회의, GitHub 저장소 연결, Git 저장은 맥에서 처리한다. 화면 종료나 네트워크 단절이 AI 실행을 자동 취소하지 않으며 이전 작업 재조회와 명시적 중단을 제공한다.
- Cloudflare 공식 cloudflared를 설치하고 맥에서 바깥으로 중계 연결을 만들었다. 중계 주소 변경은 인증된 등록 API를 통해 비공개 Vercel Blob에 저장한다. Blob에는 대화나 프로젝트 파일을 저장하지 않는다.
- 맥 로그인 시 자동 실행하는 com.gggeunyoung.ideas-remote LaunchAgent를 설치했다. 실행 중 caffeinate로 자동 잠자기를 방지한다. 덮개 닫힘·수동 잠자기·종료는 막지 않는다.
- 인증 설정과 웹 비밀번호는 .runtime 내부에만 보관하고 Git에 포함하지 않는다. 구독 CLI의 로그인 토큰과 API 키를 Vercel에 복사하지 않았다.

## 확정된 결정과 결과

- 접속 웹 주소는 기존 ideas-nine-opal.vercel.app을 유지하고 실제 작업 폴더도 기존 방별 맥 경로를 유지한다.
- 다른 노트북이 회의실 웹에 참여하는 데에는 CLI 설치·프로젝트 클론이 필요하지 않다. 다른 Claude 계정으로 직접 프로젝트를 수정하는 인수인계와는 별개다.
- 구현 커밋 db0e62c를 origin/master에 푸시하고 Vercel production에 배포했다.
- 배포 링크에서 로그인 → 맥의 방 2개 조회 → AI 협업 실험실의 기존 대화·결과 로드를 확인했다.
- 실제 원격 요청 REMOTE-LINK-001로 GPT·Claude 독립 제안 2개와 상호 검토 2개를 받았다. 기존 구독 호출이며 데모나 별도 API 모드가 아니다.
- 해당 맥 작업 ID는 e2607dab-8e24-44e5-939a-433b18fd9ee4다. 완료 회의록은 작업 방의 conversations/에 저장됐다. 계획 파일은 변경하지 않았다.

## 검증

- 자동 테스트 33개 통과. 원격 무인증·위조 세션·로그아웃 후 접근 차단, 로그인 제한, 중복 ID와 동시 작업 거절, 취소, 워커 재시작 후 완료 결과 복원, Vercel origin·경로·주소 검사를 포함한다.
- 브라우저 공개 HTTPS 경로에서 실제 모델 답변을 확인했다. 테스트 서버의 모의 답변과 구분했다.
- launchctl에서 서비스 running 상태를 확인했다. 중계 연결을 종료해 자동 재연결을 시험했다.
- 중계 프로세스를 종료한 뒤 새 주소로 재연결·Vercel 등록이 자동으로 완료됐고, 기존 웹 세션에서 이후 작업도 성공했다.
- Vercel 화면의 커밋·푸시 버튼으로 작업 방의 회의록과 인수인계 2개 파일을 c4c5954에 저장해 기존 origin/master로 푸시했다. UI에서 변경 0개를 확인했다.

## 미해결 질문과 다음 행동

- 다른 물리적 노트북·휴대전화에서는 아직 직접 시험하지 않았다. 사용자는 같은 배포 링크와 회의실 비밀번호로 접속할 수 있다.
