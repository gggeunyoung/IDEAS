## 사용자 의도

- 효율적인 아이디어와 생산적인 대화를 얻는 것이 가장 큰 목적이다.
- 현재 GPT와 Claude 유료 구독, Gemini Pro를 사용한다.
- 사용자와 GPT·Claude·Gemini가 함께 브레인스토밍하고 일하는 방법을 원한다.
- 마지막 사용자 메시지 후 약 10분 무응답이면 지금까지의 내용을 푸시하도록 요청했다.

## 적용한 운영 설정
- 기존 origin: https://github.com/gggeunyoung/IDEAS.git
- 최초에는 채팅 자동화 `ideas`를 활성화했다. 5분마다 확인하는 방식이었으며, 이후 아래 사용자 요청으로 중지했다. 현재 활성 상태를 뜻하지 않는다.
- 실제 예약 실행 및 푸시 성공은 아직 검증하지 않았다. 메시지 시각 확인 불가 시 추측하지 않는다.

## 에이전트 제안 — 사용자 결정 전
- 먼저 기존 앱에서 동일한 문제에 독립적으로 답하게 하고, 답변을 교환하여 상호 비판한 뒤 사용자가 결정하는 짧은 회의 방식을 시험한다.
- 구독을 활용한 로컬 도구 연결 후보는 Codex, Claude Code, Gemini CLI다. 실제 계정 접근과 설치 상태를 확인해야 한다.
- 하나의 대화창에서 세 제공자의 API를 호출하는 공동 회의 도구를 만들 수 있다. API 비용과 구독 혜택은 별도로 확인한다.
- 역할은 일단 기획, 비판, 조사로 나누되 특정 모델의 고정된 능력으로 간주하지 않고 회의마다 바꾼다.
- 회의 흐름: 독립 제안 → 상호 검토 → 사용자 선택 → 작은 실행. 자동 토론은 2~3라운드로 제한한다.

## 후속 대화 — API 공동 회의실 구현

### 사용자 결정
- 하나의 대화창에서 세 AI를 API로 연결하는 방식을 해보고 싶다.
- 과금을 확인하되 세 AI와 함께 대화할 수 있는 구현을 우선한다.
- Claude 구독 플랜은 Pro라고 확인했다. Max 구독의 월간 API 크레딧 혜택은 적용되지 않는다.
- 후속 질문에서 기존 유료 구독으로 사용하는 높은 모델 능력을 공동 대화에서도 활용하려는 의도를 설명했다. 기존 구독 도구 연결은 검토 제안 단계이며 API 방식 취소나 구독 방식 구현을 확정한 것은 아니다.

### 저장 타이머 규칙 수정 — 사용자 요청
- 대화 중 상시 감지가 아니라 대화가 끝난 뒤부터 10분을 감지해야 한다고 명시했다.
- 에이전트 최종 답변 종료 → 단발 10분 타이머 시작 → 새 사용자 메시지 도착 시 취소 → 다음 최종 답변 종료 시 다시 시작하는 규칙으로 수정했다.
- 기존 5분 간격 반복 감지 자동화 `ideas`를 일시 중지했고 도구 응답에서 PAUSED 상태를 확인했다.
- 단발 타이머는 아직 구현하지 않았다. 현재 반복 감지와 자동 푸시는 중지된 상태다.

### 구현 결과
- 외부 패키지 없는 Node.js 로컬 회의실을 구현했다. `npm start` 후 http://127.0.0.1:3030 에서 이용한다.
- 독립 답변 3회 후 동일한 답변 묶음을 공유하여 상호 검토 3회를 진행한다. 참가자 선택, 검토 끄기, 중단, 브라우저 저장, Markdown 내보내기를 지원한다.
- 실제 API 어댑터를 작성했으며 API 키는 서버 환경변수에서 읽는다. `.env`는 Git에서 제외했다.
- 무료 데모와 실제 API 모드를 구분한다. 실제 API 키가 아직 없어 세 제공자에 대한 실제 호출은 하지 않았다.
- 자동화 테스트 7개와 브라우저 데모에서 독립 답변/상호 검토 흐름이 통과했다.

### 과금 확인과 한계
- 2026-10-11 공식 일반 텍스트 단가, 입력/출력 100만 토큰당: GPT-6.1 Sol $2/$10, Claude Sonnet 5.5 $2/$10, Gemini 3.5 Flash-Lite $0.30/$2.50.
- 각 모델의 두 라운드 합계 입력 6,000·출력 1,000토큰을 가정하면 회의당 $0.0483, 같은 길이 100회 $4.83. 실제 청구 예측이 아니라 산술 예시다.
- Claude Max 구독은 별도 신청 가능한 API 크레딧 혜택이 있으므로 정확한 플랜 확인이 필요하다. Pro는 해당하지 않는다.
- 실제 연결에는 사용자가 로컬 `.env`에 API 키를 설정하고 계정의 잔액·접근 권한을 확인해야 한다. 키를 채팅에 공유하지 않는다.

## 후속 대화 — 기존 구독을 사용하는 로컬 에이전트 연결

### 사용자 발언과 의도
- 별도 API 과금과 앱 구독을 구분하고, 이미 결제하는 계정의 능력을 이용하고 싶다고 설명했다.
- 웹에 질문하면 GPT와 Claude가 자동으로 받아서 답하고 그 답을 같은 웹 화면에 표시하는 방식을 원한다.
- 한 주제로 AI들이 서로 보완하며 초안이나 생산적인 결과물을 만들어내기를 원한다. 한 에이전트의 편향을 다른 에이전트가 보완하는 것이 이유다.
- 파일을 읽는 프로젝트 단위의 작업에도 활용하고 싶다. 자기소개서와 포트폴리오 작성 등 개인 작업과 동시에 돌릴 수 있는지도 물었다.
- 같은 폴더를 동시에 수정하면서 충돌하는 문제를 우려하고 순서 또는 역할 분담을 물었다.
- Vercel 웹 링크를 통해 개인 맥과 SSAFY 노트북에서 모두 사용하고 싶다. 맥을 상시 켜야 하는지와 클라우드 서버 임대/포트폴리오 활용도 고려했다.
- 식사하러 자리를 비우며 구현을 위해 에이전트가 사용자 도움 없이 할 수 있는 작업을 모두 자율적으로 진행하도록 승인했다.

### 에이전트 제안과 적용한 구현 선택
- GUI 앱을 직접 조작하는 대신 공식 Codex / Claude Code / Gemini CLI의 비대화형 출력을 연결한다. 앱 화면과 입력 장치를 점유하지 않고 계정 사용량 한도는 공유할 수 있다.
- CLI 기본 모델을 사용하며 앱과 동일한 모델·기능을 보장하지 않는다. 구독 방식에서 별도 API로 자동 전환하지 않는다.
- 독립 제안을 모두 받은 뒤 같은 묶음을 전달해 상호 검토한다. 초안 모드는 지정 작성자 한 명만 초안을 만들고 다른 성공한 참가자가 검토한다. 회의당 최대 6회 호출하고 종료한다.
- 프로젝트 파일은 사용자가 고른 자료의 사본만 전달하고 원본을 수정하지 않는다. 결과는 artifacts 폴더의 별도 Markdown으로 저장한다. 자동 코드 편집/병합은 아직 구현하지 않았다.
- 향후 원격 연결에는 웹 인증·작업 큐와 밖으로 연결하는 워커가 필요하다. 현재 로컬 서버를 그대로 Vercel에 배포하거나 외부에 공개한 상태는 아니다.

### 완료한 작업과 검증 근거
- 프로젝트 전용 .local-tools 폴더에 Claude Code 2.1.296, Gemini CLI 0.63.0을 설치했다. Codex는 기존 앱 번들의 설치를 사용한다.
- local-agents.mjs에 CLI 실행·구독 인증 상태 확인·API 환경 차단·취소/시간 제한·출력 파싱을 구현했다.
- project-context.mjs에 자료 선택·파일 크기 제한·환경 파일/일부 비밀정보/외부 경로/심볼릭 링크 거절·결과물 저장/다운로드를 구현했다.
- 웹에 구독/API/데모 모드, 로그인 상태 새로고침, 토론/초안 모드, 작성자 선택, 파일 선택, 결과물 다운로드를 추가했다.
- setup:local / doctor / login:gpt / login:claude / login:gemini 명령과 사용 문서를 작성했다. 로그인 키나 .env는 Git에서 제외한다.
- 자동 테스트 15개가 통과했다. 제공자를 모의 호출한 검토 순서 테스트와 실호출 검증을 구분한다.
- Codex 로그인 상태에서 ChatGPT 구독 인증을 확인했고 실제로 ‘연결 성공’ 응답을 받았다.
- 브라우저에서 GPT 구독 회의를 실행해 실제 AI 활용 실험 제안, 회의 완료, 결과물 링크를 확인했다.
- examples/experiment-brief.md를 선택하고 GPT 단독으로 독립 제안과 7일 실행 계획 초안을 실제 생성했다. 다른 AI 검토가 없음을 화면에 표시했다.
- GPT 외 Claude/Gemini를 실제 호출하여 답변을 받지는 않았다. 해당 AI 답변을 만들어서 대신 표시하지 않았다.

### 확정 상태와 미해결 질문

- 클라우드 서버 임대 또는 Vercel 배포, 원격 인증/작업 큐는 아직 수행하거나 구현하지 않았다.
- 이 Codex 채팅의 답변 종료 후 단발 10분 타이머는 아직 연결하지 못했다. 중지된 반복 자동화를 다시 켜지 않았고, 작업 중 무응답을 추정하여 커밋/푸시하지 않았다.
